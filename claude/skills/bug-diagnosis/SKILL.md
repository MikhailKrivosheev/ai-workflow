# Диагностика бага

Идея взята из `mattpocock/skills` (diagnosing-bugs, MIT), адаптирована под фронтенд-проекты.
Главное правило: **сначала надёжное воспроизведение, потом гипотезы.** Гипотезы по одному чтению кода — частая причина «исправили не тот баг».

## 0. Секреты
В команды, логи и отчёты не попадают токены, пароли, cookies, содержимое `.env`. Нужны данные из закрытой среды — попроси меня, а не обходи.

## 1. Воспроизведение (обязательно)
Найди способ увидеть баг, который можно повторить:
- падающий тест или команда (lint / typecheck / build / скрипт);
- `curl` к API;
- точные шаги в браузере (страница, ширина экрана, действия) — проверять через Playwright, если он есть в проекте, иначе описать шаги для меня;
- сравнение с базовой веткой — только во временном worktree, без stash и переключения веток.

Готово, когда: способ запущен и показал **тот самый** симптом из задачи, а не похожий.
Воспроизвести не получилось — остановись, опиши, что пробовал, и спроси у меня доступ, данные или разрешение добавить временные логи.

## 2. Сужение
Убирай лишнее (данные, шаги, компоненты) по одному, пока каждый оставшийся элемент не станет необходимым.

## 3. Гипотезы
3–5 гипотез, по убыванию вероятности. У каждой — проверяемое предсказание: «если причина в X, то при Y увидим Z».
Покажи список оркестратору (он решит, показывать ли мне), но не жди ответа, если задача не требует.

## 4. Проверка гипотез
- Один эксперимент — одна гипотеза, одна изменённая переменная.
- Временные логи помечай уникальным префиксом `[DBG-<id задачи>]`, чтобы потом найти и удалить все.
- Тормоза: сначала замер «до», потом поиск причины; не оптимизируй вслепую.

## 5. Исправление
- Если в проекте есть тесты для этой части — сначала тест, который падает на баге, потом исправление, потом тест проходит.
- Тестов в этой части нет — не вводи их без поручения; повтори способ воспроизведения из шага 1.
- Исправляй причину, а не симптом. Минимальная правка по правилам проекта.

## 6. Уборка и итог
- Способ воспроизведения из шага 1 больше не показывает баг.
- `grep -rn "DBG-<id>"` — пусто; временные файлы и прототипы удалены.
- В отчёт: причина (подтверждённая гипотеза), что исправлено, как проверено, статус — подтверждено / частично / не подтверждено.
