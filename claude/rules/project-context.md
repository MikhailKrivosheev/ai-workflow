# Контекст проекта — обязательно перед каждой задачей

Это правило действует для главного агента и для каждого субагента.

## 1. Определи проект
- Корень: `git rev-parse --show-toplevel`. Имя проекта = имя папки репозитория.
- Работай только в этом проекте. Правила, команды и решения других проектов сюда не переносятся.

## 2. Прочитай правила проекта (только чтение)
По порядку, если файл существует:
1. `CLAUDE.md`, `CLAUDE.local.md`, `AGENTS.md` в корне и во вложенных папках, относящихся к задаче.
2. `.claude/rules/**/*.md`.
3. `.claude/skills/*/SKILL.md` — составь список скиллов проекта, прочитай подходящие к задаче и следуй им.
4. `.claude/agents/` — если там есть агент с тем же именем, что и глобальный, используется проектный.
5. `README.md`, `docs/`, `CONTRIBUTING.md` — по необходимости.
6. Мои заметки: `~/ai-workflow/projects/<имя-проекта>.md`.

## 3. Определи окружение
- Пакетный менеджер — по lock-файлу.
- Версия Node.js — `.nvmrc` в нужной части проекта, `engines` в `package.json`.
- Команды lint / test / build / dev — из `package.json`, `Makefile`, документации и CI-конфигурации.
- Состояние Git — `git status`, текущая ветка (см. `git-safety.md`).

## 4. Передача контекста субагентам
Субагенты не видят переписку главного агента. Передавая задачу, всегда указывай:
- путь к проекту и к папке задачи;
- список найденных правил и скиллов проекта, которые нужно применить;
- требования из ТЗ и критерии приёмки.

## 5. Кэш контекста
- Если `~/ai-workflow/projects/<имя-проекта>.md` существует — используй его, чтобы не исследовать весь проект заново.
- Критичные сведения (команды, версии, ветки) перепроверяй по файлам проекта.
- Нашёл устаревшее или новое — обнови заметку (это мой локальный файл, его можно менять без вопроса).
