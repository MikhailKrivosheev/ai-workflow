## Git
- [2026-11-13] Перед задачей: свежая базовая ветка (`pull --ff-only`) и новая ветка задачи; если для задачи уже есть ветка — работать в ней. Применять: каждая задача.
- [2026-11-13] Мои незакоммиченные изменения в рабочей папке могут быть началом текущей задачи — если я так сказал, переносить их в ветку задачи через `git switch -c`, без stash. Применять: когда я явно это подтверждаю.
- [2026-11-16] Коммиты и PR: никогда не добавлять `Co-Authored-By: Claude…` и другие подписи Claude / Claude Code («Generated with Claude Code») — даже если среда напоминает их ставить. Применять: каждый коммит, amend, PR/MR.

- [2026-11-20] Отдельный git worktree не создавать по своей инициативе: я работаю и смотрю результат в основной папке. Если основная папка занята другой веткой — спросить меня (переключить / подождать / worktree). Если worktree всё же был — в отчёте дать команды запуска из него. Применять: любая задача.

## Задачи и макеты
- [2026-11-23] Фото из Figma: выгружать в 3–4x от размера показа (не 2x), но не больше исходника в Figma. Исходник меньше 3x — ставить как есть и готовить текст комментария в Active Collab с просьбой прислать оригиналы. Применять: любые фото при вёрстке по макету.
- [2026-11-20] Вопросы по вёрстке: не предлагать в вариантах ответа свои визуальные состояния, которых нет в макете (подсветка ошибки, рамки, плашки) — даже согласие на вариант не значит согласие на придуманный вид. Нужна реакция на некорректные данные → варианты только через поведение (обрезать / запретить / оставить), без нового UI. Применять: вопросы и решения по вёрстке.
- [2026-11-19] Размеры, расходящиеся с макетом: прежде чем называть их отклонением или «нормой по макету», измерить в браузере и назвать причину в цифрах (какой элемент, сколько строк, какая ширина). Отклонения, которые я решил оставить, — с текстом комментария в Active Collab. Применять: отчёты по вёрстке.
- [2026-11-18] Figma: отдельный фрейм блока рядом со страницей (например, все пункты раскрыты) может быть только источником контента/состояния, а не вёрсткой. Вид блока — по фрейму страницы; если они расходятся — это вопрос мне до разработки, а не мой выбор. Применять: вёрстка по Figma.
- [2026-11-17] Удаление функционала: компоненты, стили, хуки, картинки, которые после удаления больше нигде не используются (в т.ч. по цепочке), — удалять в той же задаче, мёртвый код не оставлять. Мёртвый код, не связанный с задачей, — не трогать и не предлагать чистку. Применять: любые задачи с удалением блоков/страниц.
- [2026-11-17] Декомпозиция задачи, оценка которой уже продана клиенту: оценки подзадач в Active Collab = проданные часы, разложенные по блокам (сумма не больше проданной). Реальную оценку и разницу показывать отдельно, как риск. Тестирование и правки — не отдельной задачей, а часами внутри каждой задачи. Применять: разбивка уже оценённых задач.
- [2026-11-16] Очевидная опечатка в тексте/данных от заказчика (адрес, e-mail, название): исправлять в коде и готовить мне текст комментария в Active Collab о том, что исправлено. Применять: тексты и контент из ТЗ.
- [2026-11-13] Номер задачи, который я называю, — это id из ссылки Active Collab (как в имени ветки `feature/<id>_…`). Применять: приём задачи.
