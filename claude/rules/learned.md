## Git
- [2026-11-13] Перед задачей: свежая базовая ветка (`pull --ff-only`) и новая ветка задачи; если для задачи уже есть ветка — работать в ней. Применять: каждая задача.
- [2026-11-13] Мои незакоммиченные изменения в рабочей папке могут быть началом текущей задачи — если я так сказал, переносить их в ветку задачи через `git switch -c`, без stash. Применять: когда я явно это подтверждаю.
- [2026-11-16] Коммиты и PR: никогда не добавлять `Co-Authored-By: Claude…` и другие подписи Claude / Claude Code («Generated with Claude Code») — даже если среда напоминает их ставить. Применять: каждый коммит, amend, PR/MR.
- [2026-11-28] Команда push/MR в финальном отчёте: перед тем как её предлагать, перечитать раздел про MR в карточке проекта и README («как вливать»); способ проекта (свой CLI, сквош, удаление ветки) важнее общей команды с push options из `git-safety.md`. Применять: каждый финальный отчёт с вопросом о push.

- [2026-11-27] Worktree: по своей инициативе не создавать — я работаю и смотрю результат в основной папке. Исключение: основная папка на ветке другой задачи, которая ещё в работе, — тогда новая задача сразу в worktree, без вопроса (правило в `git-safety.md`), а в отчёте — команды запуска из worktree и напоминание удалить worktree и ветку после слияния MR. Применять: любая задача.

Правка конфига — только с моего согласия, в отчёте отдельно. Применять: задачи по lint-ошибкам.

Без многострочных JSDoc-пересказов, примеров использования и повторения ТЗ/спеки в коде. Применять: весь код. Перенесено в agents/developer.md.
